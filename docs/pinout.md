# Підключення DeskLight

Єрмак Олександр Віталійович, ІО-32. Форма B, Wokwi; фізичного стенда немає.

| Пін MCU | AF / режим | Блок → пристрій | Arduino / morpho | Рівень і підтяжка | Обґрунтування |
|---|---|---|---|---|---|
| PA0 | analog, без AF | ADC1 IN0 → LDR AO | CN8.1 A0 / CN7.28 | 0..3.3 В, без pull | DS13867 табл. 12; окремий ADC, не зайнятий LED |
| PB0 | input, без AF | GPIO ← PIR OUT | CN5.3 D10 / CN10.34 | OUT 3.3 В, MCU pull-down | DS13867 табл. 12; не використовує UART чи I²C |
| PB8 | AF6, open-drain | I²C1 SCL → MPU SCL | CN5.10 D15 / CN10.3 | pull-up 4.7 кОм до 3.3 В | DS13867 табл. 15; шина з ЛР1 |
| PB9 | AF6, open-drain | I²C1 SDA ↔ MPU SDA | CN5.9 D14 / CN10.5 | pull-up 4.7 кОм до 3.3 В | DS13867 табл. 15; парний вивід I²C1 |
| PA2 / PA3 | AF1 | USART2 TX / RX ↔ monitor | VCP / CN10.35 / CN7.37 | 3.3 В, без pull | DS13867 табл. 13, UM2953 §6.9; збережено UART ЛР1 |
| PA5 | output | LED LD4 | CN5.6 D13 / CN10.11 | HIGH увімкнено | UM2953 §6.10; немає силового виходу |
| PA4 | output | ADC_MARK → analyzer D4 | CN8.3 A2 / CN7.32 | 3.3 В, без pull | DS13867 табл. 12; вільний службовий GPIO |
| PC13 | input | B1 user button | CN7.23 | обв'язка плати | UM2953 табл. 12; не змінює режими DeskLight |

Роз'єми перевірено за [UM2953 rev 2, рис. 7 і табл. 11](https://www.st.com/resource/en/user_manual/um2953-stm32-nucleo64-board-mb1717-stmicroelectronics.pdf#page=19).
AF та корпус LQFP48 перевірено за [DS13867 rev 4, табл. 12–15](https://www.st.com/resource/en/datasheet/stm32c031c6.pdf#page=32).
Периферію визначає [RM0490](https://www.st.com/resource/en/reference_manual/dm00781702.pdf), розділи RCC, ADC, I²C та USART.
PA13/PA14 залишені для SWD. DMA, SPI, PWM не використовуються. Камери й SPI-flash у PRD немає; їхні транзакції не можна показати у цій схемі.

## Монтаж моделі

1. З'єднати GND плати, всіх сенсорів і аналізатора.
2. MPU VCC і LDR VCC → nucleo:3V3.1; PIR VCC → nucleo:5V.1.
3. MPU AD0 → GND, адреса 0x68. INT, XDA, XCL не використовуються.
4. SCL/SDA → PB8/PB9, по 4.7 кОм до 3.3 В. На фізичному модулі спочатку перевірити наявні підтяжки.
5. LDR AO → PA0, DO вільний; PIR OUT → PB0.
6. Monitor RX ← PA2, TX → PA3. Аналізатор D0=SCL, D1=SDA, D2=UART_TX, D3=PIR, D4=ADC_MARK, D5=LED, D6=UART_RX.

## Адреса й ідентифікація

MPU6050: 7-бітна адреса 0x68 при AD0=0; WHO_AM_I 0x75 очікується 0x68. Адреса 0x69 використовується лише для навмисної перевірки NACK. GPIO PIR та аналоговий LDR не мають ID-регістрів; їхня самоперевірка означає доступність входу, не доказ справності фізичного датчика.

## Тактування та живлення

HSI, SYSCLK, PCLK1 = 48 МГц. I²C TIMINGR=0x20303E5D: PRESC=2, SCLDEL=3, SDADEL=0, SCLH=62, SCLL=93. Програмовані high+low = (63+94)×62.5 нс = 9.8125 мкс; синхронізація й фільтри додають час. Ціль Standard mode 100 кГц підлягає перевірці записом.

ADC: 12 bit, PCLK/4 = 12 МГц, sample 160.5 циклів, conversion 12.5 циклів. Теоретично 14.4167 мкс. ADC_MARK охоплює весь HAL-виклик, тому його ширина не дорівнює чистому conversion time. UART 115200 8N1: 8.6806 мкс/біт, BRR ≈417.

MPU чіп: VDD 2.375..3.46 В, gyro+accel typical 3.8 мА, запас на breakout 10 мА. LDR дільник 10 кОм: максимум 0.33 мА, резерв модуля 5 мА. Дві підтяжки при LOW: 2×3.3/4700 = 1.40 мА. Проєктний резерв додаткового навантаження 3V3 = 16.4 мА. Це бюджет, не виміряний maximum. PIR живиться від 5 В; конкретний фізичний модуль не обрано, його піковий струм і OUT треба виміряти. UM2953 §6.5.2 задає 500 мА для регулятора разом з платою; гарантований залишок без струму плати невідомий. Силового приводу немає.

## Відхилені розкладки

- PIR на PA3 зайняв би UART RX і завадив командам.
- LDR на PA5 конфліктує з LD4 і цифровим виходом.
- I²C на PA9/PA10 вимагає зміни перевіреної конфігурації ЛР1 без вигоди для DeskLight.

Wokwi не перевіряє RC-фронти, шум ADC, струм, перевантаження, реальний OUT PIR чи механічне кріплення. Перед фізичним монтажем потрібні осцилограф, мультиметр і перевірка конкретних модулів.
