# Профіль зайнятості задач DeskLight

Окрема діагностична прошивка STM32C031 зберігає HAL і додає маркери GPIO. Вона відрізняється від прошивки S1/S2/S3: SHA-256 діагностичного ELF `62c103b0855b6de9acb81f39dfa5eb166aed52ce17b94f41e2ffb1b44e53bb88`, HEX `e479289736d5ba595c90d773286dd5610dc6c9ddac45ef3d06cdd4618d0fc4ee`; вихідний виміряний ELF S2 `d4c6ed31844d8988d0530fddeb7923e3aed11502e20d534d9e1c462bf6516843`. Запис не є частиною годинного S2. Основні файли прошивки в корені репозиторію маркерами не змінювались.

Wokwi з номінальними датчиками; D0=PA8 — фактично викликані foreground-ділянки: обслуговування UART, прийняті команди, ініціалізація, PIR, ADC, IMU, контроль і запланований save. Порожні перевірки готовності й проміжний spin не охоплено. Блокувальний polling/HAL усередині задачі включено. Асинхронна передача після повернення функції не включається цілком. ISR усередині HIGH потрапляє до результату, зовні не охоплюється. D1=PA9 — 100 порожніх калібрувальних імпульсів.

У повному вікні 5–15 с модельного VCD HIGH тривав 6,133421975 с, 61,33421975%, 100396 фронтів. Окремі половини — 61,33473% та 61,3337095%. Порожні імпульси мають ширину 250 нс; їх добуток на кількість включень еквівалентний 0,25099 п.п., але не є повною поправкою (інструкції за межами імпульсу, зміна темпу циклу, ISR). Це не вимір фізичного MCU чи загальної core-utilization. VCD закінчується на 46,57644575 с; вікно 5–15 с повністю збережено. Пізнє UART-підключення не підтверджує початкові повідомлення і подане без змін.

Для аналізу локально розпакуйте `capture.vcd.gz` у `capture.vcd`, потім виконайте `python3 analyze_vcd.py capture.vcd --start 5 --end 15`; для підвікон використовуйте 5–10 та 10–15. Файл стиснуто без зміни оригіналу: SHA-256 розпакованого VCD `99c94f24e87c60c7c9cd9ebaafc2a5441c32e06394447b14726eba0c3bb5ac48`; розпакованого UART `5d519a0c8db6ae312ff6cf56dd572aea17ef751fb2ed6bddd845236ab381a096`. `result.json`, `half1.json`, `half2.json` зберігають результати. `test_analyzer.py` перевіряє обрізання меж вікна, калібрування і відхилення короткого захвату.

Для відтворення **діагностичного варіанта** в окремій копії вихідного дерева застосуйте `markers.patch` з кореня, скопіюйте `diagnostic-build-id.h` до `firmware/Board/build_id.h` і зберіть окремо; результат нової збірки потрібно ідентифікувати власним хешем. Для відтворення саме цього запуску використовуйте збережені тут ELF/HEX, `diagram.json` і `wokwi.toml`, врахувавши порт 42743. Перебудова чи інша версія симулятора можуть змінити результати.
